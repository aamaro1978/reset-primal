## 📖 STORY

As a **DevOps Engineer**,
I want to **set up a production PostgreSQL database with connection pooling and automated backups**,
So that **the Reset Primal application has a secure, scalable, and reliable database infrastructure**.

---

## ✅ ACCEPTANCE CRITERIA

### Given-When-Then Format

**Given** the production environment is ready
**When** I provision the PostgreSQL database
**Then** it should be configured with:
- PostgreSQL 15+ with optimized settings (shared_buffers, max_connections=200)
- PgBouncer for connection pooling (min 10, max 100 connections)
- SSL/TLS encryption for all connections
- Automated backups to S3 (daily, retained 30 days)
- Database size: Initial 20GB volume, auto-scaling enabled
- RTO: < 30 minutes, RPO: < 1 hour

**Given** Prisma migrations are ready
**When** I run migration setup
**Then** the database schema should be:
- Created from `prisma/schema.prisma`
- All tables present (users, purchases, products, audit_logs, etc.)
- Indexes created for query optimization
- Foreign key constraints enforced
- Initial seed data loaded (if applicable)

**Given** the database is deployed
**When** connection from application is attempted
**Then** it should:
- Connect successfully using environment variables
- Support connection pooling via PgBouncer
- Log all connections to audit table
- Handle connection timeouts gracefully
- Fail over to replica (if configured) automatically

## 📋 TASKS

### Task 3.1.1: PostgreSQL Production Setup
- [ ] Provision PostgreSQL 15 instance (RDS or self-hosted)
  - [ ] Configure shared_buffers = 25% of RAM
  - [ ] Set max_connections = 200
  - [ ] Enable SSL/TLS with certificate
  - [ ] Configure pg_stat_statements extension
  - [ ] Set up replication user for backups
- [ ] Create database `reset_primal_prod`
- [ ] Create application user `app_user` with appropriate permissions
- [ ] Test connection from development machine
- [ ] Document connection string and credentials in `.env.production`

### Task 3.1.2: PgBouncer Connection Pooling
- [ ] Install and configure PgBouncer
  - [ ] Set pool_mode = `transaction` for application compatibility
  - [ ] Configure min_pool_size = 10, max_pool_size = 100
  - [ ] Set default_pool_size = 25
  - [ ] Enable connection timeout = 600 seconds
- [ ] Create PgBouncer systemd service
- [ ] Test connection pooling with `pgbouncer -R` reload
- [ ] Verify pool statistics via pgBouncer admin console
- [ ] Monitor connection usage and adjust pool sizes if needed

### Task 3.1.3: Backup Configuration
- [ ] Create S3 bucket `reset-primal-backups-prod` with versioning
- [ ] Configure bucket encryption (KMS)
- [ ] Set bucket lifecycle: Delete old backups after 30 days
- [ ] Create IAM role for database backup service
- [ ] Set up automated daily backups (01:00 UTC)
  - [ ] Full backup daily
  - [ ] WAL archiving for point-in-time recovery
- [ ] Test backup restoration process
- [ ] Document backup procedure in DISASTER-RECOVERY.md

### Task 3.1.4: Prisma Schema & Migrations
- [ ] Review current `prisma/schema.prisma`
- [ ] Update data sources to use production database URL
- [ ] Create migration: `npx prisma migrate create production_setup`
- [ ] Run migrations: `npx prisma migrate deploy`
  - [ ] Verify all tables created
  - [ ] Verify indexes created
  - [ ] Verify constraints enforced
- [ ] Seed initial data if required
- [ ] Update Prisma client to production mode
- [ ] Generate Prisma types: `npx prisma generate`

### Task 3.1.5: Database Monitoring Setup
- [ ] Create CloudWatch Dashboard for database metrics:
  - [ ] CPU utilization
  - [ ] Storage usage
  - [ ] Active connections
  - [ ] Query performance (slow query log)
  - [ ] Backup status
- [ ] Set up CloudWatch alarms:
  - [ ] CPU > 80% → Alert
  - [ ] Disk > 85% → Alert
  - [ ] Connections > 150 → Alert
  - [ ] Backup failed → Critical Alert
- [ ] Enable Enhanced Monitoring (granular metrics)
- [ ] Configure log exports to CloudWatch Logs

### Task 3.1.6: Connection Validation & Testing
- [ ] Write connection test script in Node.js
  - [ ] Test direct PostgreSQL connection
  - [ ] Test PgBouncer pooled connection
  - [ ] Measure connection latency (target: < 50ms)
  - [ ] Test connection timeout handling
- [ ] Run load test with 50 concurrent connections
- [ ] Verify application can connect and execute queries
- [ ] Test graceful shutdown with pending connections
- [ ] Document any performance bottlenecks found
